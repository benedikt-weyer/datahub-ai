# Contributing to DataHub AI

First off, thank you for considering contributing to DataHub AI! It's people like you that make DataHub AI such a great tool.

We welcome contributions in various forms, including bug reports, feature requests, documentation improvements, and code contributions.

## Getting Started

Before you begin:

1.  Make sure you have a [GitHub account](https://github.com/signup/free).
2.  Fork the repository on GitHub.
3.  Clone your fork locally:
    ```bash
    git clone https://github.com/YOUR_USERNAME/datahub-ai.git
    cd datahub-ai
    ```
4.  Set up your development environment. Instructions can usually be found in the `README.md` or a dedicated `DEVELOPMENT.md` file. (If these don't exist yet, consider adding them!)
5.  Create a new branch for your changes:
    ```bash
    git checkout -b my-feature-branch
    ```

## How to Contribute

### Reporting Bugs

If you find a bug, please ensure the bug was not already reported by searching on GitHub under [Issues](https://github.com/benedikt-weyer/datahub-ai/issues). If you're unable to find an open issue addressing the problem, open a new one. Be sure to include a title and clear description, as much relevant information as possible, and a code sample or an executable test case demonstrating the expected behavior that is not occurring.

### Suggesting Enhancements

If you have an idea for an enhancement, please first discuss the change you wish to make via a GitHub issue before making a change. This ensures that the proposed enhancement aligns with the project's goals and avoids duplicate effort.

### Pull Requests

1.  Ensure any install or build dependencies are removed before the end of the layer when doing a build.
2.  Update the README.md with details of changes to the interface, this includes new environment variables, exposed ports, useful file locations and container parameters.
3.  Increase the version numbers in any examples files and the README.md to the new version that this Pull Request would represent. The versioning scheme we use is [SemVer](http://semver.org/).
4.  You may merge the Pull Request in once you have the sign-off of two other developers, or if you do not have permission to do that, you may request the second reviewer to merge it for you.

#### Code Style

Please adhere to the coding style used throughout the project. If applicable, run any linters or formatters configured for the project.

#### Testing

Ensure that your changes include relevant tests and that all tests pass.

#### Commit Messages

Please follow conventional commit message standards. (e.g., `feat: add new login endpoint`, `fix: resolve issue with user authentication`, `docs: update contribution guidelines`).
